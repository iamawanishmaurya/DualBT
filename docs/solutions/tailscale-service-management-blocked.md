# Tailscale Service Management Blocked

- Problem: [2026-05-24-tailscale-service-management-blocked.md](../problems/2026-05-24-tailscale-service-management-blocked.md)
- Timestamp: 2026-05-24 17:31:00 IST
- Status: Environment-blocked, not fully solved inside this sandbox.

## What Failed

The requested `tailscale down`, `systemctl stop tailscaled`, `systemctl disable tailscaled`, and package removal attempts could not stop or remove Tailscale from inside this sandbox.

## What Worked

The workspace confirmed the resolver source and permission boundary. `/etc/resolv.conf` is generated by Tailscale and points at `100.100.100.100` plus `fd7a:115c:a1e0::53`. The current shell is non-root, cannot access the systemd bus, cannot connect to the Tailscale daemon socket, and cannot use sudo because the container has `no new privileges` set.

## Why It Worked

Inspection commands do not require host-level privileges. Stopping/removing Tailscale does require host-level access to systemd, the Tailscale daemon socket, or package-managed system files.

## Researched Options

1. Run `tailscale down`.
   - Trade-off: Official CLI disconnect path, but it needs access to the local `tailscaled` socket and failed here.
2. Stop/disable `tailscaled` through systemd.
   - Trade-off: Correct host service fix, but this sandbox cannot connect to the system bus.
3. Remove the Tailscale package through the host package manager.
   - Trade-off: Correct uninstall path when package-managed, but sudo/root is unavailable and the visible binaries are not owned by a listed dpkg package.
4. Restore non-Tailscale Linux DNS resolver configuration.
   - Trade-off: Could fix DNS if the only issue is `/etc/resolv.conf`, but `/etc` is outside the writable workspace and earlier direct-IP HTTPS tests also failed.
5. Run the plain Git push from a host shell outside this sandbox after stopping/removing Tailscale there.
   - Trade-off: Most efficient remaining path because it can change the host network state and use the existing local Git commands.

## Decision

The requested Tailscale removal cannot be completed from this sandbox. The efficient fix is to stop/remove Tailscale or restore DNS on the host environment with root/systemd access, then run `./scripts/push-github.sh` from `/home/astra/codex/DualBT`.
